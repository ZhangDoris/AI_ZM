# 2.3 阶段审核改造

阶段审核改造是临床研究智能预筛系统的核心审批模块，支持审批类型、审批阶段、项目阶段三层可配置模型，实现预筛、筛选、入组等各临床研究阶段的统一审批流程电子化管理。


---

## 2.3.1 审批类型配置

### 2.3.1.1 功能描述

审批类型配置是阶段审核改造的基础数据模块，用于统一管理审批类型名称、编码、排序、颜色等属性。管理员可在系统管理中对审批类型进行新增、修改、删除、启用/停用操作，并支持在列表中通过上移/下移按钮直接调整排序，为后续审批阶段和项目阶段配置提供标准化数据源。

### 2.3.1.2 能力要求

- 能够对审批类型进行新增，填写审批类型名称、编码、排序、颜色、备注等信息
- 能够对审批类型进行修改，加载选中记录后编辑保存
- 能够对审批类型进行删除，删除前校验是否被阶段或项目引用，已引用的类型禁止删除并给出提示
- 能够对审批类型进行启用/停用，停用前校验是否有阶段正在使用，有使用时禁止停用并给出提示
- 支持审批类型编码唯一性校验，新增和修改时均须验证
- 能够以表格形式展示审批类型列表，包含名称、编码、排序、颜色标签、状态开关、更新人、更新时间等字段
- 支持在列表中通过上移/下移按钮直接调整审批类型排序，排序变化即时生效并同步更新序号
- 排序调整受边界约束：首条记录不可上移，末条记录不可下移
- 支持按名称模糊搜索、按状态筛选

### 2.3.1.3 输入输出需求

**表格 3-1 审批类型配置输入输出表**

|------|---------|---------|------------|------|
| In1 | 输入 | 审批类型名称 | 用户输入 | 最多5个汉字，不可重复（必填项） |
| In2 | 输入 | 审批类型编码 | 用户输入 | 英文字母、数字、下划线组成，最多20个字符（必填项） |

## 2.3.2 审批阶段配置

### 2.3.2.1 功能描述

审批阶段配置用于定义临床研究中的各个审核阶段（如预筛阶段、筛选阶段、入组阶段等），每个阶段可关联多个审批类型、配置阶段颜色与排序，为项目阶段设置提供中间层数据支撑。管理员可对审批阶段进行新增、修改、删除、启用/停用操作，并支持在列表中通过上移/下移按钮直接调整阶段排序。

### 2.3.2.2 能力要求

- 能够对审批阶段进行新增，填写阶段名称、排序、审批类型（多选）、颜色、备注等信息
- 能够对审批阶段进行修改，加载选中记录后编辑保存
- 能够对审批阶段进行删除，删除前校验是否被项目引用，已引用的阶段禁止删除并给出提示
- 能够对审批阶段进行启用/停用，停用前校验是否有项目正在使用该阶段
- 支持阶段名称唯一性校验
- 能够从已启用的审批类型配置中多选关联审批类型，至少选择1个
- 能够以表格形式展示审批阶段列表，包含阶段名称、排序、关联审批类型标签组、颜色标签、状态开关、更新人、更新时间等字段
- 支持在列表中通过上移/下移按钮直接调整阶段排序，排序变化即时生效并同步更新序号
- 排序调整受边界约束：首条记录不可上移，末条记录不可下移

## 2.3.3 项目阶段设置

### 2.3.3.1 功能描述

项目阶段设置在项目管理编辑/新建页面中，允许项目管理员为每个研究项目配置启用哪些审核阶段，并为每个阶段指定审批流程、设置知情必填规则、填写阶段备注。项目保存后，匹配详情页将按此处配置的阶段动态生成Tab，患者在不同阶段的审批流程也据此自动匹配。

### 2.3.3.2 能力要求

- 支持在项目编辑/新建页面中配置审批阶段，从已启用的审批阶段中多选
- 为每个选中的阶段配置审批流程：选择该阶段下的审批类型并指定审批人
- 支持配置「知情必填」开关（是/否），控制该阶段是否必须完成知情同意
- 支持为每个阶段独立启用/禁用以下功能模块：入排阶段、筛选表、合并药物、合并症、思考链，不同阶段可启用不同的模块组合
- 支持为每个阶段填写备注说明
- 支持启用/停用项目阶段配置，控制该项目下各阶段的整体生效状态
- **支持配置「匹配详情新版页面」**：选择是否启用新版匹配详情页面，启用后可配置默认查看版本偏好
- **支持配置新版页面默认查看偏好**：默认查看新版本或默认查看旧版本（仅启用新版页面时可配置）
- 项目配置保存后，匹配详情页按阶段配置动态生成阶段Tab
- 患者进入某阶段后，提交审批时自动筛选该阶段配置的审批类型列表
- 支持查看各阶段审批完成进度

## 2.3.4 智能筛选-患者列表-项目匹配和提交审核

### 2.3.4.1 功能描述

智能筛选-患者列表是用户对患者进行项目匹配和提交审核的操作入口。用户可通过「仅项目匹配」按钮执行匹配操作，匹配完成后对符合条件的患者进行预提交或直接提交审核。系统根据项目设置的阶段及审核类型自动进行匹配校验，并在跨阶段匹配时弹出提示。

### 2.3.4.2 能力要求

- 支持「仅项目匹配」功能：根据项目设置中的审核阶段 + 审核类型对患者进行匹配，匹配结果为匹配状态的患者展示在列表中
- 匹配状态为"匹配中""未提交""筛败""驳回""流程内审核通过"的患者，可点击「预提交」按钮
- 点击预提交后弹出选择审核类型弹窗，用户选择一个审核类型，后台判断是否跨阶段匹配（即该审核类型所属阶段是否与患者当前阶段一致）
- 若跨阶段匹配，弹窗提示"检测到您已跨阶段，匹配成功后系统将自动为您提交。"
- 支持「匹配并预提交」功能：用户选择审批流程 + 引用信息，后台自动根据所选流程对应的审核类型 + 项目设置中该审核类型所在的审批阶段进行匹配，匹配完成即预提交
- 匹配完成但未预提交的患者，可点击「提交审核」按钮，选择审核类型后后台同样进行跨阶段匹配判断
- 若跨阶段，弹窗提示"检测到您已跨阶段，匹配成功后系统将自动为您提交。"，确认后自动根据流程对应的审核类型 + 该审核类型在项目设置中的审批阶段进行匹配并提交
- **提交审核弹窗和预提交审核弹窗中，始终展示「筛选号」和「知情时间」字段**：默认非必填，但若项目设置中该阶段配置了「知情必填=是」，则筛选号和知情时间变为必填项，提交时需进行必填校验
- 患者编辑页面同样展示筛选号和知情时间字段，必填规则同上（根据项目阶段设置的知情必填开关决定）
- 支持按患者姓名（模糊搜索）、匹配状态、提交时间范围等条件筛选患者列表
- 支持列表分页展示，包含患者姓名、项目名称、匹配状态、提交时间、操作按钮等字段

## 2.3.6 匹配详情-阶段审核

### 2.3.6.1 功能描述

匹配详情页的阶段审核功能是审核人员执行审批操作的核心工作界面。页面顶部按项目阶段配置动态生成阶段Tab（阶段列表来源于项目阶段设置中选中的阶段，不再写死"预筛阶段/入组阶段"），患者信息按阶段组织展示。审核人员可在当前阶段Tab下查看匹配详情、筛选表、合并药物、合并症、病史资料、思考链等信息，并执行审批通过/驳回操作。

页面支持新旧两个版本：
- **旧版本**：传统Tab布局，包含匹配详情、筛选表、合并药物、合并症、病史与资料、思考链等子Tab
- **新版本**：重新设计的信息展示布局（具体布局见新版页面设计）

若项目设置中启用了新版匹配详情页，页面顶部展示版本切换入口；若未启用则仅展示旧版本。若配置了默认查看新版本，进入页面时自动展示新版本。

### 2.3.6.2 能力要求

- 支持页面顶部按项目阶段配置动态生成阶段Tab，每个Tab关联该阶段的审批流程（阶段名称来源于项目配置，不再写死）

- **旧版本匹配详情页**：保留传统Tab布局，子Tab包含匹配详情、筛选表、合并药物、合并症、病史与资料、思考链，其中合并药物和合并症为独立展示的子Tab
- **新版本匹配详情页**：全新设计的匹配详情页面布局，优化信息展示和操作体验
- **版本切换**：若项目设置中启用了新版匹配详情页，页面顶部展示新旧版本切换入口；若未启用新版则不显示切换入口
- **默认版本**：进入匹配详情页时，根据项目设置中的「默认查看版本」配置决定初始展示版本；若未配置默认版本则展示旧版本
- 支持提交审批功能：弹出审批表单，自动按患者当前阶段筛选可用审批类型
- 支持审批操作：通过/驳回，填写审批意见/驳回原因
- 支持右上角展示阶段印章（如"预筛阶段-待审批"）
- 支持查看审批记录：展示该患者在各阶段的审批历史时间线

```

## 2.3.7 H5移动端审核

### 2.3.7.1 功能描述

H5移动端审核为审核人员提供手机端审批能力，支持在移动设备上查看待审批患者列表、查看患者匹配详情、提交审批申请、执行审批操作（通过/驳回）。移动端需适配小屏幕，界面简洁高效，操作流程与PC端保持一致。

### 2.3.7.2 能力要求

- 支持在移动端查看待审批患者列表，以卡片形式展示
- 支持按患者姓名、审批阶段、审批状态等条件筛选
- 支持查看患者匹配详情，页面结构适配移动端（上下布局替代左右布局）
- 支持提交审批功能：选择审批类型、审批人、填写审批意见
- 支持审批通过/驳回操作，填写驳回原因
- 支持查看审批记录
- 支持下拉刷新列表、上拉加载更多

### 2.3.7.3 输入输出需求

**表格 3-7 H5移动端审核输入输出表**

| 序号 | 信息类型 | 字段名称 | 来源/目的地 | 约束 |
|------|---------|---------|------------|------|
| In1 | 输入 | 患者姓名 | 用户输入 | 模糊搜索 |
| In2 | 输入 | 审批阶段 | 选择 | 下拉单选 |
| In3 | 输入 | 审批状态 | 选择 | 多选（待审批/已通过/已驳回） |
| In4 | 输入 | 审批类型 | 选择 | 根据患者当前阶段筛选（必填项） |
| In5 | 输入 | 审批人 | 选择 | 系统用户选择（必填项） |
| In6 | 输入 | 审批意见 | 用户输入 | 最多500个汉字 |
| In7 | 输入 | 审批结果 | 选择 | 通过/驳回（必填项） |
| In8 | 输入 | 驳回原因 | 用户输入 | 驳回时必填，最多500个汉字 |
| Out1 | 输出 | 审核列表 | 卡片列表 | 患者卡片包含姓名、项目、阶段、状态等信息 |
| Out2 | 输出 | 患者匹配详情 | 页面 | 适配移动端的上下布局详情页 |

### 2.3.7.4 处理流程需求

```
开始
  │
  ▼
打开H5审核页面 → 自动加载待审批患者列表（卡片形式）
  │
  ▼
筛选/搜索患者
  │
  ▼
点击患者卡片 → 进入患者匹配详情页
  │
  ▼
查看患者信息（上下布局）：
  ├── 匹配详情
  ├── 筛选表
  ├── 病史与资料
  └── 思考链

  │
